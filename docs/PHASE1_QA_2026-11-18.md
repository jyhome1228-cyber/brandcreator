# BRAMER V2 · 1차 검증 결과 (2026-11-18)

## 목적 및 범위
BRAMER의 **17개 제작 항목 / 26페이지** 생성 엔진을 여러 로고 형상에서 재현 가능하게 검증한다. 현재 업로드 자료에는 **건강미 브랜드의 실제 SVG 마스터 파일이 확인되지 않아** 상표 자체의 정확한 재현 여부나 실무 승인 규정을 검증하지 못했다. 아래 결과는 **합성 테스트 로고 6종**으로 검증한 소프트웨어 품질에 한정된다.

## 발견 및 수정한 결함

| 구분 | 발견 내용 | 반영 |
| --- | --- | --- |
| 시각 영역 분석 | `SVGGraphicsElement.getCTM()`은 원본 viewBox에서 뷰포트까지의 변환을 포함할 수 있어 실제 로고의 좌표/점유율 계산 오류 가능 | 최상위 SVG `getCTM().inverse()`로 루트 좌표계로 환산 |
| 숨겨진 자산 | `defs` 등에 포함된 clipPath/mask/심볼 도형이 실제 로고 영역과 혼동 가능 | 비표시 리소스를 영역 측정에서 제외 |
| 긴 대지 여백 | 소스 파일의 viewBox 전체를 화면에 맞추면 작은 로고가 과도하게 축소됨 | 유효한 visualBounds를 기준으로 2.5% 광학 여백과 함께 표시 및 비율 계산 |
| 잘못된 분석 데이터 | 영역 좌표가 비정상적이면 콘텐츠가 잘릴 위험 | viewBox 내부 여부/치수 확인 후 원본 대지로 폴백 |
| 회귀 테스트 부재 | 26P 문서와 응용 SVG가 깨져도 TypeScript 빌드에서는 검출되지 않음 | 6종 SVG fixture 회귀검사 및 GitHub Actions 등록 |

검증 항목: **17개 목차 항목의 중복 유무**, 각 브랜드 **26페이지 생성**, 페이지 ID 중복, 제외 항목이 기본 문서에 혼입되지 않는지, 입력 문자열 XML escaping, 브랜드 소개/슬로건/연락처 반영, 선택 입력 누락 시 오기재 방지, 큰 아트보드의 크롭 동작, 모든 SVG의 XML well-formedness.

총 **15개 논리 검사**와 **198개 SVG XML 파싱 검사**를 GitHub Actions에서 통과. (6종 × [26개 가이드라인 페이지 + 명함 앞뒤면 2개 + 스티커 2개 + 레터헤드 1개 + 봉투 2개] = 198개)

실행: `npm run qa:guidelines`

## 미검증·남은 결함 리스크
1. **건강미 실로고 검증:** 실제 승인된 SVG 마스터 없이는 형태·색상·심볼 간격·그리드 정확도 판정 불가.
2. **브라우저 렌더링:** 현재 회귀검사는 브라우저 스크린샷/시각 diff가 아닌 SVG XML 구조 검증이므로 폰트 치환, 텍스트 넘침, 그래픽 대비는 별도 확인 필요.
3. **최소 사용 크기:** 코드의 추천값은 휴리스틱이며 실제 인쇄 시험 및 휴먼 검증을 거친 공식 브랜드 규정이 아님.
4. **PDF 출력:** 인쇄용 PDF의 폰트 임베딩·RGB/CMYK·도련·재단선·페이지별 레이아웃 품질 별도 검증 필요.
5. **응용 디자인:** 스티커 도무송 및 봉투 전개도는 인쇄소 기준에 맞춘 인쇄용 원본이 아닌 기본 디자인 SVG.
6. **기본 문서의 빈 입력:** 브랜드 스토리, 명함 주소 등은 필요한 정보를 입력받고 표시해야 하며 임의 작성 금지.
7. **SVG 아트보드 크롭:** 2.5% 여백 휴리스틱은 복잡한 필터/그림자/획 굵기/마스크가 viewBox 밖에 뻗는 로고에서 시각적 재검토 필요.
8. **보안·복원:** SVG 외부 자원과 브라우저별 DOM 구현 차이를 포함한 추가 검증 필요.

## 다음 실제 브랜드 검수 프로토콜
1. 해당 브랜드의 승인된 SVG 로고 1~3종(원형 포함 가능), 브랜드명/영문명/공식 색상/서체/슬로건/연락처를 준비.
2. BRAMER에서 프로젝트 생성→SVG 등록→17개 항목 생성→26페이지 PDF/SVG 및 응용 SVG 다운로드.
3. 로고, 그리드, Clear Space, 최소 크기, 금지 규정, 컬러/단색, 타이포그래피, 명함·스티커·서식을 각기 육안 검수.
4. 기존 보태니컬/브론디 실제 가이드라인을 디자인 레퍼런스로 활용해 페이지 위계·여백·가독성을 체크하되 디자인 결과물을 그대로 복제하지 않음.
5. 결함별로 재현 입력·기대 결과·실제 결과·수정 후 결과를 기록하고 회귀 테스트에 추가.

> 본 1차 QA 통과는 **프로그램 기본 구조의 기술적 유효성**을 의미할 뿐, 실브랜드 가이드라인의 디자인 품질이나 인쇄 적합성 인증이 아니다.
